# Snap Spend — Decisions

Decisions already made. Don't re-litigate; add new entries at the bottom with a date.

## 2026-11-26 — Kickoff / Phase 0

### Platform & tooling
- **D1. Expo SDK 58** (expo 58.0.26, React Native 0.88.1, React 19.3, TypeScript 6.0). New Architecture is on (default).
- **D2. `minSdkVersion` = 24**, the React Native default. Not overridden in `app.json`.
- **D3. `android/` and `ios/` are not committed** (Continuous Native Generation). Native config lives in `app.json` and config plugins; the folders are regenerated by `npx expo prebuild` / `npx expo run:android`.
- **D4. Android only.** The template's web-only helpers (`useClientOnlyValue`) were removed. Web and iOS config is left in `app.json` untouched but never tested.
- **D5. Template folders moved under `src/`** (`src/components`, `src/constants`) so `@/` → `src/` matches the CLAUDE.md folder layout.
- **D6. Line endings are LF** everywhere (`.gitattributes` + Prettier `endOfLine: lf`). This matters for the byte-for-byte golden tests.
- **D7. TypeScript 6 requires explicit `types`**: `tsconfig.json` sets `"types": ["jest"]`. Add more there if a global type package is needed.
- **D8. JDK 17 for Android builds.** The machine has JDK 25 as default. React Native's Gradle build targets JDK 17, so builds use a JDK 17 via `JAVA_HOME` (see PROGRESS.md / README for setup).
- **D9. Device testing uses wireless debugging** (`adb pair` / `adb connect` over Wi-Fi), not USB. Both phones support it (Android 11+).
- **D10. No AI attribution in git** (no `Co-Authored-By` trailers). Commits are authored by the owner only.

### Native module risk check
- **D11. `react-native-document-scanner-plugin@2.0.4`** ships a `codegenConfig` (New Architecture TurboModule) and an Expo config plugin, and wraps `play-services-mlkit-document-scanner:16.0.0`. Considered compatible with SDK 58; to be confirmed by a real build in Phase 4. Fallback if it fails: gallery import via `expo-image-picker` only, recorded as a blocker.
- **D12. ML Kit document scanner requires Google Play services** on the device. Both target phones have them. It will not work on an emulator image without Google Play.

### Spec ambiguities resolved
- **D13. Which total the Daily Log prints per receipt.** `scanned` receipts print `computedTotal` (items − discounts + charges), so each line is arithmetically consistent with its tokens, which is what the golden tests show. `total_only` / `manual` print `printedTotal`. The Review screen's sanity check is where any mismatch with `printedTotal` gets fixed before saving.
- **D14. `points` adjustments (SPAR Repont)** do not change `computedTotal` and are **not printed** in the Daily Log (SPEC §6 only defines discount and charge tokens). They are stored and shown on the Review / Detail screens.
- **D15. Receipt order within a day:** by `time` ascending, receipts with no `time` after timed ones, ties broken by `createdAt`.
- **D16. qty > 1 pcs with `unitPrice` null:** the Daily Log prints `round(lineTotal / quantity)` as the unit price.
- **D17. Non-integer pcs quantity** (rare, e.g. 1.5 pcs) prints the quantity as-is with `.` decimal (`1.5Db×…`).
- **D18. Discount/charge tokens** use the separator ` − ` / ` + ` in place of the item ` + ` separator, exactly as in golden test 3 (`… Bio bag 19Ft − Clubcard discount 100Ft …`).
- **D19. Duplicate guard** = same canonical store (after aliases) + same date + same `printedTotal`. It warns, never blocks.
- **D20. Dates and "today"** use the device's local time zone. Stored as ISO `YYYY-MM-DD` text.
- **D21. IDs** are UUID v4 strings (generator chosen in Phase 2).

## 2026-11-26 — Phase 1

- **D22. Phase 1 started before Phase 0 was finished**, at the owner's request. The device-build item of Phase 0 stays open and is done when the phone is paired. Phase 1 needs no device.
- **D23. `formatDailyLog` output** joins lines with `\n` and has no trailing newline. No receipts gives `''`, even with GRAND TOTAL on.
- **D24. Daily Log totals are computed from items and adjustments** when the log is built, not read from the stored `computedTotal` column, so an edited item always shows up in the log.
- **D25. Money helpers.** `formatAmount(n)` gives `3.894` (used inside the log); `formatFt(n)` gives `3.894 Ft` (UI). Non-integers are rounded. `parseHuf` returns `null` for anything it can't read. Spaces and `.` followed by groups of exactly 3 digits are thousands separators, `,` is the decimal separator, and a lone `.` with other than 3 digits after it is a decimal point (`12.5`). Decimals are rounded to whole forints.
- **D26. Sanity check passes** when computed equals printed, or when printed + redeemed points equals computed (the receipt printed the total after Repont, SPEC §5).
- **D27. Schema leniency.** The zod schema rejects wrong types, non-integer money, bad units, quantity ≤ 0, negative adjustment amounts and invalid dates. It quietly fixes harmless things: missing optional fields → `null`, `HH:MM:SS` → `HH:MM`, masked card number → last 4 digits (or `null`), blank strings → `null`. `lineTotal` may be negative (returned items). Unknown categories are not rejected; `normalizeReceipt` maps them to `Other`.
- **D28. Category is named `Pantry`.** The "(canned, rice, oil, spices)" in SPEC §3 is a description, not part of the name.
- **D29. `normalizedKey`** = English name + size label, lowercased, whitespace collapsed. The size isn't appended again if the name already ends with it.
- **D30. `@types/node`** is in `tsconfig.json` `types` so tests can read `docs/SPEC.md`. A test checks that the golden fixtures match the SPEC §6 blocks exactly.
